# 产品定义与 MVP 范围

> 项目代号：**JobCompass（求职指南针）**

---

## 0. 一句话定位

求职者输入一个目标岗位（如「AI 产品经理」），AI 结合整理后的公开求职信息，自动生成一条**可执行的学习成长路径 + 面经题库 + 课程推荐**。

---

## 1. 为什么做（背景与动机）

我自己就是目标用户：大三升大四，想找产品经理实习，但完全不知道要学什么——一开始连「产品经理要写 PRD、竞品分析、用户调研、画原型图」都不清楚，更不知道 AI 产品经理还要懂哪些技术概念（比如怎么调试 prompt）。

这不是我一个人的困惑。目标用户的普遍痛点是：

- 信息分散在 **小红书 / 牛客 / B站 / Boss直聘 / 知乎**，没有一个工具把它「对到你的岗位」串成一条路；
- 知道「想当产品经理」，但不知道先学什么、再学什么、要用哪个工具、面试会问什么；
- 想要「路径感」和「可打勾的执行清单」，而不是一篇篇零散的经验帖。

为什么是现在：大模型 + RAG 技术已经能把海量非结构化帖子「加工」成结构化知识；同时求职竞争加剧，大家更需要清晰路径。

---

## 2. 目标用户（MVP 聚焦）

### 主画像 P1：校园求职者（找实习 / 校招 / 秋招）

- 身份：本科大三/大四、硕士研二/研三在读
- 状态：正在投递实习/校招，方向明确，但不清楚「岗位到底要求什么、怎么准备」
- 诉求：
  1. 知道要学什么、先学什么、学到什么程度
  2. 知道面试会问什么、常考什么
  3. 知道去哪个平台、学哪些课（比如学 Axure / Figma 看哪个 B站 UP 主）
- 典型场景：看到「产品经理 / AI 产品经理」JD，却不知道从哪下手；背「八股文」但不知道考什么。

### 次画像 P2：在职转岗者

- 身份：工作 1–5 年，想转行产品 / AI 方向
- 诉求：与 P1 相同，但更看重「从现有技能迁移」和「转岗路径」

> MVP 阶段只把 P1 做透，P2 先不动（避免把范围撑大）。

---

## 3. 核心价值主张（差异化）

不是「AI 帮你总结一篇文章」，而是**把零散、非结构化的求职信息，加工成一条可执行、可校验、可打勾的成长路径**。

| 现有平台 | 问题 |
| --- | --- |
| 小红书 / 牛客（内容社区） | 内容散、靠用户自己找、质量参差 |
| B站（教程平台） | 课程多，但不知道先看哪个、看到什么程度 |
| 直接问 ChatGPT / DeepSeek | 答案泛、可能幻觉、没有可信来源、不成体系 |

**我们以「目标岗位」为轴心，把「学什么 → 用哪个课 → 面试考什么 → 练到什么程度」串起来。**

---

## 4. 核心使用场景（用户故事）

- **SC1 生成路径**：用户输入目标岗位 → 生成「岗位能力要求 / 技能树 / 分阶段学习计划」
- **SC2 面经题库**：按岗位/公司查看面经，AI 提炼「高频考点 / 常见题 / 答题框架」
- **SC3 课程推荐**：针对技能树的每一环，推荐 B站等教程，并说明「为什么学、学到什么程度」
- **SC4（后期）技能差距**：对比用户当前背景与岗位要求，给出差距和优先级

---

## 5. MVP 功能范围

### Must（第一版必须，否则产品不成立）

1. **目标岗位输入** + 个人背景（学历 / 方向 / 经验）快速勾选
2. **学习成长路径生成**：岗位要求 → 技能树 → 分阶段计划
3. **面经库**：MVP 先放 20–50 条高质样本 + AI 汇总常考考点
4. **教程 / 课程推荐**：内链 B站，AI 说明学什么、为什么学

### Should（第二版再加）

5. 岗位/职位匹配（从爬取/整理的 JD 里，找适合你的岗位）
6. 技能差距分析
7. 简历 / 求职建议、模拟面试问答

### Could（第三版 / 视情况砍掉）

8. 社区、打卡进度、商业化会员、付费 1 对 1

---

## 6. MVP 主流程

```
输入目标岗位（+可选背景）
        ↓
系统返回 4 个板块：
  ① 岗位概览（要会什么）
  ② 学习路径（分阶段 + 带打勾进度）
  ③ 面经考点（高频题 + 答题框架）
  ④ 教程推荐（B站等 + 为什么学）
        ↓
用户可收藏、勾选进度、再次进入可继续/更新
```

---

## 7. 成功指标

- **北极星指标**：每周成功生成并查看「学习路径」的独立用户数
- **辅助指标**：
  - 新用户首完率：输入 → 看到完整结果的占比
  - 回访率：7 天内再次使用
  - 面经查看率、教程跳转率
  - 内容质量：重复率、概念错误率、用户负反馈率
- **MVP 自评标准**：能用 1 个真实岗位跑通全流程，拿给 5 个同学试用，收集到有效反馈

## 8. 数据来源与合规方案（重要，需持续迭代）

### 分层数据策略（主动降低风险）

| 层级 | 说明 | 使用方式 |
| --- | --- | --- |
| L1 公开/开放数据 | 官方发布、公开接口、公开数据集 | 最合规，优先 |
| L2 用户公开帖子 | 小红书 / 牛客等公开经验帖、面经帖 | 只做摘要/结构化提取 + 回跳原文，**不整篇搬运** |
| L3 人工 + AI 生成 | MVP 冷启动：手放 20–50 条高质样本，AI 补齐讲解 | 够跑通闭环 |
| L4 爬虫（技术练习） | 小规模、限速、只碰公开内容 | 单独做、先证明能力，不深入 |

### AI 处理管道

```
采集 → 清洗 → 去重 → 过滤营销/卖课 → 概念校验（可信源 + 人工抽检）→ 分类入库
```

### 合规底线

- 不整篇转载，只做摘要 / 提炼，并保留来源链接
- 遵循平台条款，优先官方渠道；爬虫只碰公开内容、控制频率
- 不采集、不存储个人身份信息，做匿名化
- AIGC 内容明确标注「AI 生成，仅供参考」，重要概念做校验

## 9. 技术方案概要（MVP）

| 模块 | 选型 | 说明 |
| --- | --- | --- |
| 前端 | Next.js（Web 网页版） | 易开发、易分享、好演示 |
| 后端 | Python FastAPI | 你已会基本 Python，最好上手 |
| 数据库 | PostgreSQL + pgvector | 存面经/岗位 + 向量（RAG 用） |
| AI | DeepSeek API | 预算约 200 元，先跑小流量，省着用 |
| 爬虫（练习） | Python requests / playwright | 合规小规模 |
| 部署 | Vercel / Railway | 能演示即可 |

---

## 10. 风险与开放问题

- **爬虫 & 版权**：MVP 用人工 + 公开 + AI 数据规避，爬虫单独练
- **AI 幻觉 / 概念错误**：用「可信源 grounding + 人工抽检 + 免责声明」缓解
- **冷启动数据**：先手放少量高质样本跑通闭环
- **时间**：约 30 小时，按 Must 做，Should / Could 果断砍掉
